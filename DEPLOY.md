# Як запустити сайт у продакшн

Сайт складається з трьох частин, і кожна живе у своєму сервісі:

| Частина | Де живе | Що робить |
|---|---|---|
| Сайт і адмінка (Angular) | **Vercel** | Віддає готові HTML-сторінки, адмінку за адресою `/admin` |
| Прийом заявок (`/api/lead`) | **Vercel Functions** | Перевіряє заявку, зберігає в базу, шле в Telegram і на пошту |
| База даних, вхід в адмінку, фото | **Supabase** | Послуги, заявки, акаунти адмінів, сховище картинок |

Сповіщення: **Telegram-бот** (безкоштовно) і **Resend** для email (має безкоштовний тариф).

Загальний порядок: Supabase → Telegram → Resend → Vercel → домен. Займає приблизно годину.

---

## 1. Supabase — база даних

1. Зареєструйся на [supabase.com](https://supabase.com) → **New project**.
   - Region: **Central EU (Frankfurt)** — найближче до України.
   - Придумай і **збережи** пароль бази (він знадобиться лише для прямого доступу до БД).
2. Коли проєкт створиться, відкрий **SQL Editor** → **New query**:
   - встав увесь вміст файлу `supabase/migrations/0001_init.sql` → **Run**;
   - нова вкладка → встав `supabase/seed.sql` → **Run** (це 6 поточних послуг із текстами).
3. **Authentication → Sign In / Providers → Email**: вимкни **Allow new users to sign up**. Так ніхто сторонній не зареєструється (а навіть якщо зареєструється — без запису в таблиці `admins` нічого не побачить).
4. **Authentication → URL Configuration**:
   - Site URL: `https://твій-домен.com.ua`
   - Redirect URLs: додай `https://твій-домен.com.ua/admin/login` (для «Забули пароль?»).
5. Створи акаунт адміністратора: **Authentication → Users → Add user → Create new user**
   (пошта + пароль, галочка **Auto Confirm User**).
6. Дай цьому акаунту права адміна: **SQL Editor** →
   ```sql
   insert into public.admins (user_id, email)
   select id, email from auth.users where email = 'твоя@пошта.com';
   ```
   Так само можна додати ще людей (менеджера тощо).
7. **Project Settings → API Keys** — скопіюй:
   - `Project URL` → це `SUPABASE_URL`
   - `anon` / `publishable` key → це `SUPABASE_ANON_KEY` (публічний, його не страшно показати)
   - `service_role` / `secret` key → це `SUPABASE_SERVICE_ROLE_KEY` (**секретний**, нікому не показувати, нікуди не вставляти, крім Vercel)

> Безкоштовний тариф Supabase: 500 МБ бази, 1 ГБ файлів — для цього сайту вистачить із запасом.
> Безкоштовний проєкт ставиться на паузу після тижня без активності. Щоб цього не сталося,
> у `vercel.json` налаштовано щоденний автоматичний запит до бази (`/api/keepalive`).

## 2. Telegram — сповіщення про заявки

1. У Telegram напиши [@BotFather](https://t.me/BotFather) → `/newbot` → придумай назву.
   Він видасть токен виду `123456789:AA...` → це `TELEGRAM_BOT_TOKEN`.
2. Куди слати заявки:
   - **Собі особисто:** напиши своєму боту будь-яке повідомлення.
   - **У групу:** створи групу, додай туди бота, напиши в групі будь-що.
3. Відкрий у браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайди `"chat":{"id": ...}`.
   Це число (для груп воно від'ємне, напр. `-100123...`) → `TELEGRAM_CHAT_ID`.
   Кілька чатів — через кому: `111111,-100222222`.

## 3. Resend — заявки на пошту (необов'язково)

1. Зареєструйся на [resend.com](https://resend.com).
2. **Domains → Add domain** → свій домен → додай DNS-записи, які він покаже, у панелі реєстратора домену. Дочекайся статусу **Verified**.
3. **API Keys → Create** → це `RESEND_API_KEY`.
4. `LEAD_EMAIL_FROM` — адреса на твоєму домені, напр. `GeniusDev <zayavky@твій-домен.com.ua>`.
   `LEAD_EMAIL_TO` — куди слати, напр. `geniusdevgnb@gmail.com` (кілька — через кому).

> Без власного домену Resend дозволяє слати лише на пошту, з якою ти реєструвався. Якщо пошта не потрібна —
> просто не заповнюй ці три змінні, заявки йтимуть у Telegram і в адмінку.

## 4. Vercel — хостинг

> ⚠️ Безкоштовний тариф Vercel (Hobby) дозволений лише для некомерційних сайтів. Сайт компанії з послугами —
> комерційний, тож потрібен тариф **Pro** (актуальна ціна на [vercel.com/pricing](https://vercel.com/pricing)).

1. Зареєструйся на [vercel.com](https://vercel.com) через GitHub.
2. **Add New → Project** → обери репозиторій `build-site` → **Import**.
   Налаштування збірки вже лежать у `vercel.json`, нічого міняти не треба.
3. Перед **Deploy** розгорни **Environment Variables** і додай:

   | Змінна | Звідки | Обов'язкова |
   |---|---|---|
   | `SUPABASE_URL` | Supabase, крок 1.7 | так |
   | `SUPABASE_ANON_KEY` | Supabase, крок 1.7 | так |
   | `SUPABASE_SERVICE_ROLE_KEY` | Supabase, крок 1.7 (**секретний**) | так |
   | `SITE_URL` | твій домен, напр. `https://geniusdev.com.ua` | так |
   | `TELEGRAM_BOT_TOKEN` | крок 2 | для Telegram |
   | `TELEGRAM_CHAT_ID` | крок 2 | для Telegram |
   | `RESEND_API_KEY` | крок 3 | для пошти |
   | `LEAD_EMAIL_FROM` | крок 3 | для пошти |
   | `LEAD_EMAIL_TO` | крок 3 | для пошти |
   | `CRON_SECRET` | будь-який довгий випадковий рядок | бажано |

4. **Deploy**. Через 1–2 хвилини сайт буде на адресі `назва-проєкту.vercel.app`.
5. Перевір:
   - відкрий сайт → залиш тестову заявку → вона має прийти в Telegram і з'явитися в `/admin/leads`;
   - зайди в `/admin` під акаунтом із кроку 1.5 → зміни ціну послуги → онови сайт.

Кожен `git push` у гілку `main` автоматично перевикладає сайт. Push в іншу гілку створює окреме прев'ю-посилання.

## 5. Домен

1. Vercel → проєкт → **Settings → Domains → Add** → введи домен.
2. Vercel покаже DNS-записи, які треба додати в панелі реєстратора домену. Після оновлення DNS
   (від кількох хвилин до кількох годин) HTTPS-сертифікат з'явиться автоматично.
3. Онови `SITE_URL` у Vercel і Site URL у Supabase на остаточний домен → **Redeploy**.

## 6. Пошуковики (Google)

Сторінки послуг збираються в готовий HTML під час кожного деплою, тому Google бачить повний текст.
Зміни, зроблені в адмінці, відвідувачі бачать одразу, а в HTML для пошуковиків вони потраплять після наступного деплою.
Щоб це відбувалось автоматично:

1. Vercel → **Settings → Git → Deploy Hooks** → створи хук (гілка `main`) → скопіюй URL.
2. Supabase → **Database → Webhooks → Create** → таблиця `services`, події Insert / Update / Delete,
   тип **HTTP Request**, метод POST, URL — той, що скопіював.

Тепер після кожного збереження послуги сайт сам перезбирається (≈1–2 хв).

Ще варто: додати сайт у [Google Search Console](https://search.google.com/search-console) і вказати там
`https://твій-домен/sitemap.xml`; створити або оновити профіль компанії в Google Maps (Google Business Profile).

## 7. Щоденна робота

- **Заявки:** `/admin/leads` — статуси «Нова → В роботі → Виконана», нотатки, дзвінок в один дотик з телефона.
- **Послуги:** `/admin/services` — додати, змінити текст і ціну, завантажити фото (воно саме стиснеться), сховати, змінити порядок.
- **Телефони, пошта, «понад 7 років»** — у файлі `src/app/core/site.ts` (змінюються в коді, після push сайт оновиться).

## Якщо щось не працює

| Симптом | Що перевірити |
|---|---|
| Заявки не приходять у Telegram | `TELEGRAM_*` у Vercel; чи писав ти боту / чи бот у групі; Vercel → Logs → функція `api/lead` |
| В адмінці «Невірна пошта або пароль» | Користувач у Supabase → Authentication → Users, чи підтверджений (Auto Confirm) |
| «Цей акаунт не має доступу» | Чи виконано SQL з кроку 1.6 для цієї пошти |
| В адмінці жовта плашка «Демо-режим» | У Vercel не задано `SUPABASE_URL` / `SUPABASE_ANON_KEY` → додай і **Redeploy** |
| Не завантажується фото | Чи виконано весь `0001_init.sql` (він створює сховище `service-images`) |

## Локальна розробка

Потрібен Node.js 22.22+ або 24.15+ ([nodejs.org](https://nodejs.org), версія LTS).

```bash
npm ci
cp .env.example .env   # заповни значення (або залиш порожнім — буде демо-режим)
npm start              # http://localhost:4200
npm run build          # продакшн-збірка в dist/mysite/browser
npm test               # тести API заявок
```

Без `.env` сайт працює в **демо-режимі**: послуги — з вбудованих даних, адмінка пускає з будь-якою поштою,
а всі зміни зберігаються лише в цьому браузері. Зручно, щоб показати клієнту до підключення бази.

Тексти послуг за замовчуванням лежать у `src/app/core/data/seed-services.json`.
Якщо їх змінюєш — запусти `npm run seed:sql`, щоб оновився `supabase/seed.sql`.
